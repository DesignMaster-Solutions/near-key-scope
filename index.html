Key Scope

Before an AI agent gets a NEAR key, check what that key can actually do on chain, compared with what you meant to allow: the contract it may call, the methods, and the gas allowance it still has.

Read-only: one finalized public RPC query from your browser. No wallet, no signing, no private keys.

Your policy for the agent key

Public key only (about 44 characters after ed25519:). A private key is refused here.
Comma or space separated. An empty list on chain means every method.

Verdict

Fill your policy and press Check live, or use Fill example for the public guest-book.testnet key. Only the account filled in? Check live lists every key on it, worst first.

Try it in 30 seconds (judges: do X, see Y)

  1. Press Fill example, then Check live (or open ?demo=live): you should see FAIL with ALL_METHODS and a fresh block height. The policy allows only add_message; the key on chain allows every method. (Third-party public example; the narrow policy is ours.)
  2. Under the verdict, open 9 keys on this account: every key on the account, worst first, from the same query (7 FULL_ACCESS, 2 ALL_METHODS on the example). The key you checked is marked.
  3. Clear the key field and press Check live with only the account (or open ?demo=scan): the page lists every key on that account, worst first, with no policy and no verdict (the CLI's scan).
  4. Press Replay: the same verdict from the snapshot saved on 2026-10-31, offline. A replay is reproducibility, not proof of the current chain.
  5. Paste ed25519: followed by 88 characters into the key field: the page refuses it as a private key before any request is made.
  6. Download the evidence JSON and replay it with the CLI: node cli.mjs replay policy.json key-scope-evidence.json (same audit.mjs as this page).
