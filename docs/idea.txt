Problem: an AI agent on NEAR acts through an access key, and the key's name or the owner's intent says nothing about what it can really do. A key labelled "read-only agent" can be FullAccess; a function-call key with an empty method list can call every method on its receiver. Owners find out after the agent misbehaves.

Product: Key Scope is a read-only CLI that checks one selected public key against an owner policy (network, account, receiver, explicit method list, maximum remaining gas allowance) before the key is handed to an agent. It queries finalized access keys over public RPC, compares them with BigInt-exact rules, and prints a machine-readable verdict: PASS, FAIL with findings such as ALL_METHODS, FULL_ACCESS, WRONG_RECEIVER or ALLOWANCE_TOO_HIGH, or UNKNOWN on bad input. Every report carries the block hash, height, capture time and the key's observed permission, so the evidence can be re-checked later. It never reads private keys, signs or sends transactions. The demo replays a real public testnet key that allows every method while the example policy allows one; live mode fetches fresh data. A second command, scan, lists every key on an account worst first (FullAccess, every method, no gas budget, scoped) with no policy needed. 35 tests, no dependencies.

How NEAR fits: it is built on NEAR's function-call access keys, the native primitive for giving an agent limited authority. Key Scope makes that limit verifiable before delegation and fits a CI step or an agent framework's pre-flight check. Track: AI Security & Defense.
